Smart Architect

An AI-driven 2D/3D floorplan designer deployed as a single Cloudflare Worker — drive it from a chat sidebar or from the Claude iOS app, and watch the canvas update in real time.

Overview

Smart Architect hosts an interactive floorplan editor built on the open-source react-planner library. A conversational AI agent — Claude claude-opus-4-8 — edits a canonical floorplan scene through structured tools: drawing rooms, walls, doors, windows, and furniture. Every connected browser sees those edits stream in live over a WebSocket.

The defining trait of the system is that the blueprint is genuinely shared. A prompt typed into the chat sidebar and a prompt sent from the Claude iOS app both converge on the same authoritative scene held in a Durable Object, and every edit is versioned in D1. The desktop canvas is a live view onto that single source of truth.

Architecture

The browser page runs two completely separate React roots that never share components. This is deliberate: react-planner is effectively pinned to React 16, while the assistant-ui chat requires React 19. Rather than fight that, the two are decoupled into two bundles mounted side by side.

The chat path

The sidebar wires assistant-ui to the Cloudflare Agent through a runtime chain. The UI is composed from @assistant-ui/react primitives (ThreadPrimitive, MessagePrimitive, ComposerPrimitive):

useAgent            (agents/react)
  → useAgentChat    (@cloudflare/ai-chat/react)
  → useAISDKRuntime (@assistant-ui/react-ai-sdk)
  → AssistantRuntimeProvider

The worker entry

worker/index.ts routes requests three ways: /mcp* → BlueprintMCP.serve; /agents/* → routeAgentRequest (the chat agent and its WebSocket); everything else → static assets via the ASSETS binding with single-page-application fallback.

The Blueprint Document & Coordinate System

The blueprint is a react-planner plannerState JSON document. Within a layer it is organized into lines (walls), holes (doors/windows cut into walls), items (furniture and fixtures), and the areas derived from enclosed walls. Lines reference vertices by id; holes reference a line and an offset along it; items carry a position and rotation.

Coordinate system. Units are centimeters. The origin is top-left, with +x to the right and +y down. The default canvas is 3000 × 2000 cm. Generated geometry is expected to stay inside the canvas; grow it by clearing and redrawing if needed.

The Agent & Tools

The BlueprintAgent (worker/agent/blueprint.ts) is a Cloudflare AIChatAgent Durable Object. It holds the canonical scene in DO state and exposes a hybrid tool set — bulk operations for big restructures and granular operations for incremental edits. Tool execution mutates DO state via setState, which broadcasts to connected browsers.

ToolDescription
get_blueprintInspect current geometry — exact ids and coordinates.
set_blueprintReplace the entire scene with a complete plannerState (bulk).
clear_canvasEmpty the scene (optionally resize the canvas).
new_roomAdd a closed rectangular room (four walls) at a given footprint.
add_wallAdd a single wall segment between two points, reusing existing corner vertices.
add_holeCut a door/window into an existing wall line at an offset (0..1).
add_itemPlace a furniture/fixture item at a position with a rotation.
remove_elementRemove a wall, hole, or item by id.
save_versionSnapshot the current scene into the D1 version DAG.
list_versionsList saved versions.
restore_versionRestore a previously saved version.

Catalog vocabulary

react-planner elements draw their valid types and default properties from the catalog (app/catalog/):

  • Lines — the line type in use is wall. Each line has two vertices and a list of holes.
  • Holes — openings cut into a wall: door, window, and similar types, each with a line and an offset (0..1).
  • Items — freestanding furniture/fixtures placed at (x, y) with a rotation, each with a type from the catalog.

Because agent-produced elements often omit per-element properties, the client's normalizeScene() fills any missing property from the catalog's default values before rendering (see Realtime).

Realtime & the Blueprint Bus

The two React roots talk only through a tiny vanilla bridge on window.__planner, defined in app/index.js:

window.__planner = {
  getScene(),               // current react-planner scene JSON
  loadScene(scene),         // load a scene into the canvas (normalized first)
  onSceneChange(fn),        // subscribe to scene changes
}

When a tool mutates DO state, the change broadcasts over WebSocket. On the client, the useAgent onStateUpdate callback hands the new scene to window.__planner.loadScene, which re-renders the canvas — so an edit issued from the chat sidebar, the Claude iOS app, or any other connected client appears live everywhere.

Scene normalization (and why Autosave was removed)

Agent-produced elements frequently omit per-element properties — for example a door's width or height. Before calling react-planner's loadProject, normalizeScene() fills every missing property from the catalog element's default value, so the renderers don't crash on incomplete input. The catalog is the single source of truth for those defaults.

Important

The react-planner Autosave plugin was removed. It restored un-normalized scenes from localStorage, bypassing normalizeScene() and crashing the renderers. The Durable Object and D1 are the source of truth — do not re-introduce Autosave.

AI Gateway BYOK setup

The model is Claude claude-opus-4-8, routed through Cloudflare AI Gateway in bring-your-own-key (BYOK) mode. The gateway is named default-gateway and the base URL is:

https://gateway.ai.cloudflare.com/v1/<ACCOUNT_ID>/default-gateway/anthropic

The worker reads the gateway token from a Secrets Store binding (await env.CLOUDFLARE_AI_GATEWAY_TOKEN.get()) and passes it as the provider apiKey (sent as the x-api-key header). The gateway recognizes that token, authenticates the request, and swaps in the real Anthropic key it has stored.

Gotcha — read this

Do not use a cf-aig-authorization header for this. In BYOK mode the token belongs in the provider apiKey — that is the correct contract. The real Anthropic key must be stored in the dashboard under AI Gateway → default-gateway → Provider Keys.

See worker/ai/anthropic.ts for the implementation. No secret values live in the repo.

MCP Server & connecting Claude iOS

The BlueprintMCP Durable Object (worker/mcp/blueprint-mcp.ts) is a Cloudflare McpAgent served at /mcp over MCP Streamable HTTP. Its tools do not maintain their own state — they proxy to the same BlueprintAgent instance (getAgentByName(env.BlueprintAgent, 'default') → getScene / syncScene). It exposes the same vocabulary as the chat agent: get_blueprint, new_room, add_wall, add_hole, add_item, remove_element, set_blueprint, clear_canvas, save_version, list_versions, restore_version.

Add it to the Claude iOS app

  1. In the Claude iOS app, add a custom MCP connector.
  2. Point it at https://smart-architect.hacolby.workers.dev/mcp.
  3. Ask Claude to draw or modify a room. The MCP tools mutate the same blueprint your desktop browser is viewing.
  4. Watch the change appear on the desktop canvas in real time over the WebSocket.

Because both surfaces resolve to the agent instance named "default", a phone and a desktop are editing one shared document.

Versioning with D1

Persistence and history live in the D1 database smart-architect-db, accessed via Drizzle ORM (worker/db/). The versions table is modeled as a directed acyclic graph: every row carries a parent_version_id.

That structure means you can rollback, clone, and branch the blueprint without ever losing prior versions — restoring an older version creates a new node rather than discarding what came after. The sidebar exposes Save and History (restore) controls, and the agent/MCP tools save_version, list_versions, and restore_version drive the same DAG.

Debug Panel

The sidebar includes a collapsible debug log panel — hidden by default, toggled open on demand, and auto-revealed when an error occurs. It captures console output alongside agent and scene events. A shadcn button labelled "Copy as agent prompt" copies the captured logs already wrapped in a coding-agent debugging prompt, so a user hitting a frontend bug can hand a ready-to-paste report straight to a coding agent.

The sidebar is styled with Tailwind v4 (preflight disabled) plus scoped shadcn tokens, all contained within chat/.

Heads up

Local wrangler dev cannot read the remote Secrets Store secret, so the live LLM only works on the deployed URL. The canvas, sidebar, and static routes run locally, but to verify the agent end-to-end you must deploy.

Known Limitations

  • Single-tenant, no auth. The agent/MCP instance name is hardcoded to "default".
  • The /mcp endpoint is currently unauthenticated — anyone with the URL can edit the blueprint.
  • The live LLM does not work in local dev — local wrangler dev cannot reach the remote Secrets Store. Test the model path on the deployed URL.
